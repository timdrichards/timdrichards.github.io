What a concept map is

A companion to Recipe 43 (exams students can prepare for), for anyone who has not drawn a concept map before. It shows what one is, two ways to make one, and two examples from courses I teach: COMPSCI 326 Web Programming and COMPSCI 426 Scalable Web Systems.

What it is

A concept map is a picture of how the ideas in a unit connect. It has two parts.

  • Concepts, the nouns of the unit, each in a box: HTTP request, route handler, cache.
  • Labeled links, arrows between the boxes, each with a short verb phrase on it: HTTP request arrives at Express server. Read along an arrow and you get a sentence, which is the point. Every link is a claim a student can get right or wrong.

Two things separate a concept map from a list of terms or a mind map. The links carry words, not just lines, and the map has cross-links that tie distant parts of the unit together. Cross-links are where understanding shows: a student who can say how the method and URL pick the route handler knows more than one who can define both.

Each map starts from a focus question, the one question the map answers. It keeps the map to one unit and stops it from becoming a glossary.

Two ways to draw one

As a diagram. Boxes and arrows, on paper or a whiteboard. It shows the whole structure at once and makes cross-links easy to see. It is the better choice in class, from memory, with a pen.

As a nested list. The same map, typed as an outline. Each line is one link, written as a sentence: the concept above it, the verb phrase, the new concept in bold. Indenting follows the main path; a cross-link gets its own line marked ↪. It loses some of the picture, but it can be typed into a Canvas text box, compared side by side, and pasted into an AI tool. It is the better choice online or in a very large course.

Both carry the same information. The examples below show each map both ways.

Example 1: Web Programming (COMPSCI 326)

Focus question: How does a form submission reach the database and come back to the page?

Solid arrows follow one request from the browser to the database and back. Dashed arrows are cross-links.

The same map as a nested list:

  • The browser renders an HTML form.
    • The form's submit event runs a fetch() call.
      • fetch() sends an HTTP request.
        • The request names a method and URL.
          • ↪ The method and URL pick the route handler.
        • The request arrives at the Express server.
          • The server runs middleware.
            • Middleware parses the body for the route handler.
              • The route handler reads and writes the database.
              • The route handler returns an HTTP response.
      • ↪ fetch() resolves with the HTTP response.
        • The response carries a status code and JSON.
          • The JSON is used for a DOM update.
            • ↪ The DOM update changes what the user sees in the browser.

A student who has memorized the parts can name every box. The links are harder. Which part picks the route handler? Where does the body get parsed? What does fetch() give back, and when? Those are the questions a unit exam asks, and the map shows a student which ones they cannot answer yet.

Example 2: Scalable Web Systems (COMPSCI 426)

Focus question: How does a web system keep up when traffic grows?

Solid arrows follow a request through the system. Dashed arrows are cross-links, which is where the trade-offs are.

The same map as a nested list:

  • Traffic growth is spread by a load balancer.
    • The load balancer sends each request to any of the stateless app servers.
      • Being stateless makes horizontal scaling possible.
        • ↪ Horizontal scaling absorbs traffic growth.
      • App servers check the cache first.
        • On a miss, the cache reads the database.
          • The database copies to read replicas.
            • Read replicas lag behind, causing eventual consistency.
        • ↪ The cache lowers response time.
        • ↪ Stale cache entries are another case of eventual consistency.
      • App servers hand slow jobs to a message queue.
        • The queue feeds workers.
          • Workers write results to the database.
        • ↪ The queue keeps response time low.

Here the cross-links are the course. Each part of a scalable system buys speed or capacity at a price, and the price shows up somewhere else: a cache and a replica both trade freshness for speed. A student who draws the first column but none of the dashed arrows knows the parts and not the design.

Using it as exam practice

A concept map helps most when students draw it from memory, then check it. Building a map with the notes open beats rereading (Nesbit and Adesope 2006), but it does less than practicing recall (Karpicke and Blunt 2011). Drawn from memory, a map works about as well as a practice test (Blunt and Karpicke 2014). The recall is what does the work, so the notes stay closed until the map is done.

Ten minutes of class, with nothing to grade:

  1. Give the focus question and 8 to 12 concepts. Put them on a slide. In a 426 review, that is the list from the second map above.
  2. Notes closed, five minutes. Students draw the map on paper, with a verb phrase on every arrow and at least two cross-links.
  3. Two minutes with a neighbor. Each finds one link the other has that they missed, and one link they disagree about.
  4. Notes open, three minutes. Fix what is wrong, fill what is missing. Then show your map on the slide.

For a course online or too big to walk around, give the same task as an ungraded Canvas survey in the nested-list form. Read a few, not all, and post one announcement on the links most people missed.

What to look for

You don't need to grade a map to learn from it. Three things show the gaps.

  • Unlabeled lines. A line with no words, or "is related to", hides whether the student knows the link. Ask for a verb.
  • No cross-links. A map that is only a tree is a table of contents. The links across branches are the understanding.
  • Wrong direction or wrong verb. "The database calls the route handler" is a misunderstanding you can fix before the exam, not after.

The prompt

Use it to draft your own map of a unit, the one you show on the slide. Check every link; the AI will be fluent and sometimes wrong.

Here are my lecture notes for one unit of a computer science course:
[paste them]

Focus question: [the one question this unit answers]

Write a concept map as a nested list. Use 10 to 14 concepts from the
notes. Each line is one link written as a sentence: the concept above
it, a short verb phrase, then the new concept in bold. Indent to follow
the main path. Add three or four cross-links, each on its own line
starting with "↪", that connect concepts in different branches. Avoid
vague verbs such as "relates to" or "involves". Then list the five links
students are most likely to get wrong, and why.
